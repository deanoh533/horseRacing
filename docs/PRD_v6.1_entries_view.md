# PRD v6.1 — 출마정보 비교 화면 추가

> 작성: 2026-05-26
> 상태: 기획 확정, 구현 대기

---

## 1. 배경 (Why)

### 1.1 발견된 문제

v6.0까지의 서비스는 "AI 예측기"로 설계됐지만, **실제 사용자(본인)의 사용 패턴이 기획과 다르게 나타남:**

- AI 예측 1위만 확인하고 끝 — 18개 항목 점수는 거의 안 봄
- 18개 항목 점수가 **추상적("0.85점")**이라 직관적이지 않음
- 경주/출전마의 **raw 정보**를 자기 시각으로 보고 싶은데 그 화면이 없음
- 결과: AI를 맹신하거나, AI를 무시하거나 → 어느 쪽이든 사용자 주체적 판단이 빠짐

### 1.2 핵심 인사이트

> **"AI 예측은 여전히 메인이지만, 사용자가 그 예측을 검증할 수 있는 도구가 필요하다."**

기존 포지셔닝 "AI 예측기"는 그대로 유지하면서, **검증 레이어**를 추가해야 한다.

## 2. 새 포지셔닝

| | 기존 (v6.0) | 신규 (v6.1) |
|------|-------------|-------------|

## 3. 변경 사항 (What)

### 3.1 신규: 출마정보 비교 화면

**URL:** `/race/{meet}/{date}/{rcNo}/entries`

**목적:** 한 경주의 모든 출전마를 **표 형태로 한눈에 비교**할 수 있는 화면.

**구조:**
```
┌─────────────────────────────────────────────────┐
│ [< 뒤로] 서울 3R 1800m 핸디캡                    │  ← 경주 메타 헤더
├─────────────────────────────────────────────────┤
│ 🤖 AI 예측 1-3위 (요약 박스, 가볍게)              │
│   🥇 1번 마사춘향  🥈 5번 청풍명월  🥉 3번 ...    │
├─────────────────────────────────────────────────┤
│ ┌───┬──────┬───┬───┬──────┬────┬──────┬────┐ │
│ │번 │마명  │나/성│부담│레이팅 │상금│기수  │최근 │ │  ← 정렬 가능한 표
│ ├───┼──────┼───┼───┼──────┼────┼──────┼────┤ │
│ │ 1 │마사춘향│4세♂│57.0│85   │5천만│박태종│1-3-2-5-1│
│ │ 2 │청풍명월│5세♀│55.0│92   │1.2억│조성곤│2-1-1-3-2│
│ │...│      │   │   │      │    │      │     │ │
│ └───┴──────┴───┴───┴──────┴────┴──────┴────┘ │
│   각 행 클릭 → /horse/... 말 상세로 이동          │
└─────────────────────────────────────────────────┘
```

**기본 정렬:** 출주번호(pthr_no) 순. 컬럼 헤더 클릭으로 재정렬.

**핵심 컬럼 (필수):**
1. 출주번호 (pthr_no)
2. 마명 (hr_name)
3. 나이/성별 (ag, gndr)
4. 부담중량 (burd_wgt)
5. 레이팅 (ratg)
6. 수득상금 통산 (erng_sump)
7. 기수명 (jcky_nm)
8. 최근 5경주 폼 (history-derived, "1-3-2-5-1" 형식)

**선택 컬럼 (사후 모드에서 추가):**
- 실제 착순 (ord)
- 단승 배당 (win_odds)
- 인기 순위 (popularity)

### 3.2 대시보드 변경

각 경주 카드에 **두 개의 입구**를 추가:

```
┌───────────────────────────────┐
│ 서울 3R 1800m                  │
│ AI 예측: 마사춘향 (87.3점)      │
│                               │
│ [🤖 AI 예측 보기] [📋 출마정보] │  ← 두 버튼
└───────────────────────────────┘
```

- `[🤖 AI 예측 보기]` → 기존 `/race/{meet}/{date}/{rcNo}` (그대로 유지)
- `[📋 출마정보]` → 신규 `/race/{meet}/{date}/{rcNo}/entries`

### 3.3 기존 화면 영향

**변경 없음:**
- 대시보드 (날짜 선택, 경주 목록) — 카드 내부에 버튼만 추가
- 경주 상세 (RaceDetail) — AI 예측 카드 그대로
- 말 상세 (HorseDetail) — 그대로 (다음 P1에서 18항목 표시 개선 예정)

## 5. 신규 KRA API 통합 (P0b)

### 5.1 추가할 API

| API | 용도 | 데이터 단위 | 캐싱 전략 |
|-----|------|-------------|-----------|
| **API6_1** | 구간별 기록 (furlong 단위 통과 시간) | 경주 단위 | 경주 후 1회 sync |
| **API18_1** | 일별 훈련 정보 (조교 이력) | 일자 + 마번 | 매일 sync |
| **jkpresult** | 기수 정보 (기수별 성적) | 기수 단위 | 주 1회 sync |

### 5.2 기존 활용 (이미 구현됨)

- **API284** (`getBloodInfo()`) — 혈통 지수: 이미 KRAClient에 있음, 출마정보 페이지에서 활용
- **horseinfohi** (`getHorseInfo()`) — 부마/모마: 이미 있음

### 5.3 제외된 API

- **API15_2** (경주마 성적 정보): 통산 출주수/1-3위/승률/입상률/상금 모두 **이미 race_entries로 계산 가능**.
  유일한 신규 정보(등급별 상금 분해)는 가치 대비 추가 API 호출 비용이 커서 보류.
  필요 시 race_entries 기반 SQL aggregate 뷰로 대체.

### 5.4 출마정보 페이지에서의 활용 (P0a ↔ P0b 통합)

출마정보 비교 표의 **각 행 클릭 시** 펼침 영역(또는 모달)에 다음 정보 노출:

```
┌─ 클릭한 출전마 펼침 영역 ────────────────┐
│ [혈통 정보]  (API284, 기존)              │
│   부마: ○○○ / 모마: ○○○                 │
│ [최근 훈련]  (API18_1, 신규)             │
│   2026-05-20 본주로 4F 53.2초            │
│ [구간 기록]  (API6_1, 신규, 사후만)      │
│   G3F: 35.2 / G1F: 12.1 ...             │
│ [기수 최근 성적]  (jkpresult, 신규)      │
│   최근 30일 12경주 / 1위 3회 (25%)       │
└──────────────────────────────────────────┘
```

→ 이 펼침 영역은 P0a 비교 화면이 갖추는 핵심 차별화 기능.

## 5. 구현 가이드 (P0)

### 5.1 추가할 파일

- `client/src/pages/RaceEntries.tsx` — 신규 비교 화면 컴포넌트
- 라우팅 추가: `client/src/App.tsx` 또는 라우터 설정 파일

### 5.2 수정할 파일

- `client/src/pages/Dashboard.tsx` (또는 경주 카드 컴포넌트) — 버튼 두 개 분리
- 라우터 설정 — `/race/.../entries` 라우트 추가

### 5.3 데이터

기존 `useHorsesByRace(rcDate, meet, rcNo)` 훅 그대로 사용 가능.
`useHorseHistory()` 훅을 각 출전마에 대해 호출해서 "최근 5경주 폼" 계산.

**성능 주의:** 출전마 N마리 × 5경주 = N개 history 쿼리. React Query 캐시로 중복 호출 방지 가능. 출전마가 14마리 이하면 충분히 빠를 것.

### 5.4 컬럼 정렬 로직

- 클라이언트 사이드 정렬 (서버 호출 불필요, 한 경주는 최대 14마리)
- 헤더 클릭 → useState로 sortKey/sortOrder 관리
