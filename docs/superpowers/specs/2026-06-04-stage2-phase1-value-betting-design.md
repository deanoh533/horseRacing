## 0. 한 줄 요약

Phase 0이 찾은 엣지(**중배당 구간 × 모델 P(top3) 상위터셀**)에 **연승 베팅했다면 ROI가 양수인가**를 과거 데이터로 검증하는 읽기 전용 백테스트. 양성이면 Phase 2(B: calibration+Kelly+UI), 음성이면 value 트랙 보류·Stage-1만 프로덕션화(B3).

---

## 1. 배경·동기

Phase 0(엣지 probe)에서 **같은 win_odds 구간 안에서 모델 상위터셀이 하위터셀보다 top3율이 +10%p(중배당 4-7배), +5%p(7-15·15-30) 높고, 인기마(<2·2-4)는 약함**을 6분기 일관으로 확인했다. 이는 "통계적 엣지(정보)"의 입증이다.

그러나 Phase 0은 **top3율 분리**까지만 봤다. 실제 베팅 수익(ROI)은 별개 질문이다 — top3율이 높아도 배당이 낮으면 돈을 잃을 수 있다. Phase 1 = **엣지의 화폐화 검증**.

### 데이터 제약이 구조를 정함 (중요)

- `race_entries.plc_odds`(연승 배당)는 **입상마(연승 적중)에게만 non-null** (2024~2026 입상마 100% 채움 확인). 베팅 시점에 *전 마필*의 연승 배당은 알 수 없다.
- 베팅 시점에 전 마필이 가진 시장 신호는 여전히 **`win_odds`(단승, 전 마필)** 뿐.

→ 따라서:
- **value 판정(어디에 거나)** = 베팅 시점 정보인 `win_odds` 구간 + 모델 P(top3). Phase 0 엣지 검정과 정확히 동일.
- **payout 계산(얼마 따나)** = 입상 시 실제 `plc_odds`.

---

## 2. 베팅 규칙 (핵심)

경주 안 각 말에 대해:

- **건다 조건:** `win_odds`가 중배당 구간(주 타깃 **4~15배**) **그리고** 경주 내 모델 P(top3) 순위가 **상위 1/3 터셀**.
- **스테이킹:** 정액(flat) — 베팅마다 동일 **1000원**. (A는 고정. Kelly는 Phase 2.)
- **정산:** 입상하면(연승 적중 = 8두 이상 top3, 5~7두 top2) `plc_odds` 배당 회수, 아니면 베팅액 손실.
  - 입상 여부 = `plc_odds is not null`로 판정(데이터가 KRA 연승 규칙을 이미 반영).
- **ROI** = (총 회수액 − 총 베팅액) / 총 베팅액.

> 배당 구간은 4~15를 **주 타깃**으로 보되, 백테스트는 **모든 구간**(`<2 / 2-4 / 4-7 / 7-15 / 15-30 / 30+`)을 쪼개 출력 — 어디가 +인지 데이터가 말하게 함(정직성).

### 터셀 정의 (Phase 0과 동일 — 배당구간 풀 기준)

- Phase 0의 엣지는 **배당구간 풀 전체**에서 모델 점수 터셀로 측정됐다(경주 내가 아님). 백테스트도 **검증된 그 엣지를 그대로** 화폐화하려면 같은 정의를 쓴다.
- **컷오프는 train 데이터로 결정**(look-ahead 회피): 각 배당구간에서 train 말들의 모델 점수 상위 1/3 경계(2/3 분위)를 컷오프로 잡고, test 말의 점수가 그 컷오프 이상이면 "상위터셀".
- 베팅 조건 = **(win_odds 중배당) AND (점수 ≥ 해당 구간 train 컷오프)**.
- (참고: Phase 0 probe는 test 풀에서 터셀을 냈으나, 베팅 주장엔 train 컷오프가 정직 — 숫자가 미세하게 다를 수 있음.)

## 3. 데이터·구현

- **모델 점수 산출:** 기존 `data/training_matrix.jsonl`(모델 feature·ord·win_odds·race_date·meet·rc_no 포함) + Stage-1 로지스틱(`src/engine/models/logistic.ts`의 `fitLogistic`, `alignFeatures`)으로 테스트셋 P(top3) 산출. Phase 0 `probe_market_edge.ts`와 동일 파이프라인.
- **추가 조인 1개:** `race_entries`에서 `plc_odds`를 **`(race_date, meet, rc_no, hr_name)`** 키로 페이지 로드해 조인. (입상마만 non-null = 정확히 필요한 값.)
  - 행렬은 경주 내 말을 `hr_name`으로 식별하고 `extract_training_matrix.ts`가 이미 `win_odds`를 `hr_name`으로 조인하는 검증된 패턴 → 동일 키 재사용. `pthr_no` 불필요.
- **학습/테스트 분할:** `train < 2025` / 테스트 `2025~` (look-ahead 없음). Phase 0과 동일.
- **산출물:**
  - 읽기 전용 스크립트 `scripts/backtest_value_betting.ts`
  - 헬퍼 `src/engine/analysis/valueBacktest.ts` (베팅 선정·정산·집계 순수 함수 — 단위 테스트 대상)

## 4. 출력 & 판정 게이트

### 출력

배당구간 × (전체 / 분기별) 표:

```
배당구간 | 베팅수 | 적중수 | 적중율 | 평균배당 | 회수율(ROI) | 분기일관성
4-7     |  ...   |  ...   |  ...  |  2.3     |   +6.2%     | 6/6 양수
7-15    |  ...   |  ...   |  ...  |  4.1     |   +3.1%     | 5/6 양수
...
```

- 각 배당 구간마다 전체 ROI + **분기별 ROI**(일관성 확인).
- 베이스라인 비교(선택): 같은 구간 "전 마필 무작정 연승 베팅" ROI(시장 takeout 손실 기준선) 대비 얼마나 나은지.

### 게이트

- ✅ **양성:** 어떤 배당 구간이 **ROI > 0 + 다분기 일관(대략 5/6분기↑ 양수) + 표본 충분(베팅수 충분)** → Phase 2(calibration+Kelly+UI) 확장 정당화.
- ❌ **음성:** 전 구간 ROI ≤ 0 또는 분기 들쭉날쭉 → 엣지가 화폐화 안 됨. value 트랙 보류, Stage-1만 프로덕션화(B3).

---

## 5. ⚠️ 정직성 장치 (필수)

- **확정배당 근사:** `plc_odds`·`win_odds`는 **사후 확정값**. 베팅 시점 실제 배당과 다를 수 있음(특히 연승 배당은 사후만 존재). → ROI는 **낙관적 상한**으로 해석. 스펙·출력에 명시.
- **거래비용:** 연승 배당은 이미 KRA 공제율 반영된 **순배당** → 별도 takeout 차감 불필요. (배당 100원 단위 반올림 등 미세 오차는 무시.)
- **다중검정:** 배당 구간은 §2로 **사전 고정**. 즉흥 추가 슬라이스 금지. 판정은 **다분기 일관성 + 베팅수**로만. 단일 분기의 큰 ROI는 노이즈로 취급.
- **표본 경고:** 구간 × 분기로 쪼개면 셀이 작아짐. 베팅수 적은 셀(대략 n<100)은 참고만.
- **look-ahead 없음:** 모델 train<2025 / 테스트 2025~. 행렬 feature는 이미 as-of. win_odds는 경주 전 시장가.

---

## 6. 범위

- **본 Phase 1 (A):** `backtest_value_betting.ts` + `valueBacktest.ts`(순수 함수·단위 테스트) + 구간별/분기별 ROI 출력. **calibration·Kelly·UI 없음.**
- **분리 (별도 spec, A 양성 시):** Phase 2 (B) = 확률 calibration(isotonic/Platt) + 시장 대비 EV value 산식 + Kelly 스테이킹 + 라이브 추천 UI(예상지 저평가마 모듈). value 판정 로직만 A와 공유, A=과거검증 / B=라이브추천+UI로 분리.
- **무관:** B3(Stage-1 로지스틱 프로덕션화)는 이 트랙과 독립 — 병행 또는 후속.
