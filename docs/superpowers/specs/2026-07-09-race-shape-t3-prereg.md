# 경주 전개 shape_signal — t3 후속 검증 사전등록

> 2026-07-09 · 상태: 사용자 승인 (판정 구간·합격선 버튼 확정)
> 선행: `2026-07-08-race-shape-features-design.md` (피처 구현·t2 판정 미채택) · 트랙: docs/status/04-signals.md

## 1. 배경 — 왜 t3로 다시 검증하는가

t2 사전등록 판정(2026-07-09)은 미채택(Δ+0.2%p < +0.5%p). 단 **참고 진단에서 top3 라벨 계열이 일관 양수**였다:
- Logistic(t3) 57.9→59.4 (**+1.5%p**, 분기 5/6 양수) · GBDT(t3) 55.2→57.3 (+2.1%p)
- 도메인 정합: 신호의 원천(H3~H6 역전 확률)이 "3착 안에 드는가" 역학이므로 top3 라벨이 자연스러움.

**오염 문제**: 위 +1.5%p는 2025Q1~2026Q2 시험 데이터에서 *발견*한 값 → 같은 구간으로 판정 금지(시험지 미리 본 재시험). 2022-01~2024-05 백필(+4,110경주, G3F 커버리지 100% 검증 완료 2026-07-09)로 **2024H2를 신선한 시험 구간**으로 확보 → 여기서만 판정한다.

## 2. 판정 스펙 (사전 확정 — 결과 보고 후 변경 금지)

| 항목 | 값 |
|---|---|
| 판정 지표 | 롤링 표 **Logistic(t3)** 1순위 연승(show)률 Δ (ON−OFF) |
| ON / OFF | `--include shape_signal` / `--exclude shape_signal` (동일 스펙 통제 A/B) |
| 시험 구간 | **2024Q3·2024Q4** (2024H2, 약 880경주) — overall은 이 두 분기 합산만 |
| 학습 구간 | 2022-01-01 ~ 시험 분기 직전 (확장 윈도우, 기존 rollingBlocks 방식) |
| par cutoff | **20240701** (첫 시험 분기 시작일 — 시험 경주에 미래 정보 0) |
| **합격선** | **overall Δ ≥ +0.5%p AND 분기별(2개) Δ 모두 양수 → 채택. 미달 → 기각** |
| 참고 진단 (판정 미사용) | GBDT(t3)·Logistic(t2) Δ, 2025Q1~2026Q2 재확인 런, 게이트 3면, 로지스틱 계수 |

- 표본 주의(사전 인지): 2024H2 ~880경주는 노이즈 ±1%p 가능. 그럼에도 무오염 구간 단독 판정이 사전등록 원칙에 부합(사용자 선택 A).
- 합격선은 t2 판정과 동일 기준 유지(사용자 선택). 관찰값 +1.5%p 근거의 상향 조정은 하지 않음(사후 정보로 기준을 만들지 않는다).
- 채택 시: 04-signals 채택 기록 + promote 절차는 별도 사이클. 기각 시: shape_signal 트랙 종결(코드는 휴면 자산 유지).

## 3. 벤치마크 재구성 요건 (판정 실행의 전제)

현재 `scripts/benchmark_all.ts` 하드코딩 3곳을 CLI 파라미터화한다. **플래그 미지정 시 기존 기본값 그대로** — 기존 `npm run benchmark` 동작·출력 불변이 회귀 기준.

| 현재 하드코딩 | 플래그 | 기본값 | t3 판정 런 |
|---|---|---|---|
| `FIRST_TEST = {2025, 1}` | `--first-test YYYYQn` | 2025Q1 | `2024Q3` |
| `collectRaces(db, 20240101, 99991231)` | `--from YYYYMMDD` / `--to YYYYMMDD` | 20240101 / 99991231 | `--from 20220101 --to 20241231` |
| `SHAPE_PAR_CUTOFF = FIRST_TEST 시작일` | (유도값 유지 — 별도 플래그 없음) | 20250101 | 20240701 (자동) |

- `--to 20241231`로 데이터 끝을 자르면 롤링 블록이 2024Q3·Q4 두 개만 생성 → overall 행이 곧 판정값 (분기 합산 후처리 불필요).
- `scripts/benter_twostage.ts`의 FIRST_TEST는 이번 범위 밖 (벤치마크만).

### 판정 명령 (기록용)

```bash
npm run benchmark -- --from 20220101 --to 20241231 --first-test 2024Q3 --exclude shape_signal   # OFF
npm run benchmark -- --from 20220101 --to 20241231 --first-test 2024Q3 --include shape_signal   # ON
# 참고 재확인(판정 아님): --from 20220101 --first-test 2025Q1 로 ON/OFF
```

## 4. 테스트

- 단위: `--first-test` 파싱(YYYYQn), `--from/--to` 가 collectRaces 범위에 반영, cutoff 유도값.
- 회귀: 플래그 없이 실행 시 기존과 동일 경주 수·동일 게이트 결과. 기존 테스트 전체 + `npm run build` 통과.
