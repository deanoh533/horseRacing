# 페이스 조건부 성적 (pace_fit · pace_sens) — 설계 스펙

> 2026-07-15 브레인스토밍. F-001 페이스 예측 UI 논의 중 사용자 가설로 전환.
> 상태: 설계 승인 → 구현·검증 대기. F-001 UI는 **보류** (본 검증 결과가 UI 문구에 영향 — 검증 후 재개).

---

## 1. 배경·가설

- 기존 시험(⑲ 성향×페이스 one-hot 12칸)은 "이 말이 접전에 유리한가"를 **성향 분류(평소 위치)로 간접 추정** → 계수 ~0 (흡수, 2026-06-16 종결).
- 사용자 가설: 레이팅·속도지수·전개(shape)는 **환경 무관 일반 실력**만 담는다. 보고 싶은 것은
  **환경(페이스)이 변할 때 누가 일관적으로 강하고, 누가 특정 환경에서만 터지는가** — 간접 추정이 아니라
  그 말의 **과거 전적을 페이스별로 쪼갠 직접 측정**.
- 사례: 투혼파이터(7/10 부경6R, 22배 우승) — 평균 지표는 평범, 조건 맞으면 폭발하는 유형.
- **이 조작화(환경 조건부 실전 성적)는 게이트에 올라간 적 없음** — shape_d6_best(피크 능력)와 다른 각도.

## 2. 피처 정의 (후보 3개)

말 h의 이번 경주 예상 페이스를 P(HOT/NORMAL/SLOW), 과거 경주 중 실측 페이스가 P였던 것들을 S_P라 할 때:

| 피처 | 정의 | 의도 |
|---|---|---|
| `pace_fit` | mean(finish_ratio of S_P) − career_finish_ratio, **shrinkage 적용** (아래) | 이번 예상 페이스에서의 초과 성적. 통산 대비 **델타**로 만들어 일반 실력과 분리(흡수 회피) |
| `pace_sens` | 페이스 버킷별 finish_ratio 평균의 최대−최소 (버킷 2개 이상 있을 때) | 환경 민감도 — 크면 "환경 타는 말", 작으면 "꾸준한 말" |
| `pace_fit_n` | \|S_P\| (해당 페이스 과거 경주 수) | 표본수 공급 — 모델이 "적은 표본의 델타는 덜 믿기"를 학습 (기존 `*_n` 패턴) |

- finish_ratio = (ord−1)/(fieldSize−1) — 기존 position_ratio 정의 재사용.
- 델타 방향: 음수 = 그 페이스에서 통산보다 잘 뜀 (finish_ratio는 작을수록 좋음). 부호 해석은 모델에 위임.
- **shrinkage**: `pace_fit_raw × n/(n+k)` — 표본 n이 작으면 0으로 수축. k 초깃값 3, **probe 분포 보고 확정** (직관 단독 결정 금지).
- 결측: S_P 비었으면 `pace_fit__missing=1` + 값 0 (기존 missingFlag 패턴). pace_sens는 버킷 1개 이하면 결측.

## 3. 페이스 라벨 정의

**이번 경주 (예상)**: 기존 `computePaceType` 그대로 (출전마 구성: 선두권 성향 ≥3 HOT / ≤1 SLOW). 산식 변경 없음.

**과거 경주 (실측)**: 그 경주의 **실제 초반 기록**으로 라벨링 — 출발 200m 평균(s1f, `race_sectional_stats.avg_s1f` 산식과 동일 원천)을 같은 거리·트랙 par와 비교.

- par 대비 빠름 임계 → HOT, 느림 임계 → SLOW. **임계값은 probe로 분포 확인 후 확정** (예: 상·하위 30% 분위 시작점).
- 구성 기반(그 시절 출전마 성향 재계산) 대신 실측을 쓰는 이유: 실제로 벌어진 전개(추정 오차 0) + 재계산 비용 회피.
- 예상(구성)×과거(실측)의 정의 비대칭은 의도된 것 — "비 예보에 대비해 실제 비 온 날 성적을 본다".
- 커버리지 주의: 구간기록 없는 경주 ~3% (서울 2024+ 97~100%) → 라벨 불가 경주는 S_P에서 제외.

**확정값 (probe:pace-form 2026-07-15)**: 경주 7805건·커버리지 99.8% 실측 → PACE_HOT_DELTA=−0.11 · PACE_SLOW_DELTA=+0.11 (delta 30/70 분위, 직관 초깃값 ±0.25초 대비 절반), PACE_FIT_SHRINK_K=3 유지(HOT 버킷 n 중앙값[0 제외]=3과 일치).

## 4. 누수 점검

- 과거 경주의 실측 데이터 사용은 **as-of 원칙 위반 아님** — 그 경주들은 이번 경주 시점에 이미 종료·공표된 정보.
- 이번 경주 자신의 실측 페이스는 절대 사용 금지 (예상 페이스만). 추출 시 `race_date < 이번 경주` 필터 필수.
- 라벨 원천(s1f)은 race_entries 사후 필드지만 **과거 경주 행에서만** 읽음 — wg_hr(마체중) 같은 라이브 누수 아님.

## 5. 검증 절차 (사전등록)

1. **probe** (`probe:pace-form` 신설) — 로컬 미러/매트릭스에서 분포·표본수·커버리지 확인 → s1f par 임계·shrinkage k 확정. DB 0회.
2. **게이트A** (`probe:corr`) — **진단 전용: 상관관계 보고만, 탈락 판정 없음** (2026-07-15 사용자 결정). 특히 성향 one-hot·shape 계열과의 |r| 기록.
3. **게이트B = 통제 A/B (유일한 판정)** — 같은 스펙에서 새 피처 ON/OFF만 바꿔 5분기 롤링 벤치마크.
   - **사전등록 판정 기준: 연승(top3) Δ ≥ +1.0%p AND 5분기 중 3분기 이상 양수.** 결과 확인 후 기준 변경 금지.
   - 게이트B 한계기여 방식(피처 추가 전후 비교)은 과대보고 전례(조교 +1.8%p→통제 0) — 통제 A/B만 인정.
4. **통과 시**: 채택 기록(04-signals·메모리). **라이브 반영은 10월 재학습 사이클 합류** (L-003 동결 준수 — promote 없음).
5. **탈락 시**: 기각 기록 + **buildFeatures 내보내기 라인 즉시 제거** (shape_d6_best 교훈 — 기각 피처가 다음 재학습에 몰래 섞이는 것 방지).

## 6. 구현 개요

- `src/engine/features/paceForm.ts` 신설: 과거 경주 리스트(각각 finish_ratio·실측 페이스 라벨) → 3피처 계산. 순수함수 + 단위 테스트(TDD).
- 데이터 주입: `scorePredictor`의 as-of 경로에서 말별 과거 경주의 (finish_ratio, s1f, 거리, 트랙) 확보 — shape 파이프라인(horseShapeStats)과 같은 패턴. par 테이블은 speed figure par 재사용 가능 여부 먼저 확인.
- `buildFeatures`에 조건부 내보내기 — 라이브 v7은 스키마 필터로 무시(logisticScorer.ts:19 확인됨), 벤치마크/추출 경로에서만 유효.
- 추출: `extract:matrix` 재추출(로컬) → probe → 게이트.
