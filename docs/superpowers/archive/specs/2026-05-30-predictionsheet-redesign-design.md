---

## 1. 배경

현재 PredictionSheet(예상지)는 4열 카드 구조로 동작하지만, 두 가지 문제가 있다.

1. **예상지답지 않음** — 전통 경마 예상지(출마표)가 제공하는 정보 밀도에 미치지 못한다.
2. **직전경주 정보가 부족** — 구간기록·경기조건·기수 등 판단에 필요한 컬럼이 누락돼 있다.

사용자는 예상지를 실제 베팅 판단 도구로 쓰고 싶고, AI 예측은 검증 보조 수단으로 활용하길 원한다.

## 2. 확정된 카드 구조 (제안3)

### 2.1 전체 레이아웃

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 헤더: [번호] [마명] [성향 배지] [공백 배지]          [점수바] [총점] [AI순위] │
├──────────────┬────────────────┬─────────────────────────────┬───────────────┤
│  ① 말정보    │  ② 기수정보    │  ③ 직전경주                  │  ④ 항목점수  │
│  1.5fr       │  1.2fr         │  2.8fr                      │  1.5fr       │
└──────────────┴────────────────┴─────────────────────────────┴───────────────┘
```

grid-template-columns: `1.5fr 1.2fr 2.8fr 1.5fr`

---

### 2.2 헤더행

| 요소 | 내용 |
|---|---|
| 번호 | `pthr_no` — 크고 굵게, cyan |
| 마명 | `hr_name` — 굵게 |
| 성향 배지 | 주행 성향 분류 (도주/선행/추입 등) |
| 공백 배지 | 출전 공백일수 (`daysBetween`) — 30일+ 시 gold |
| AI 점수바 | `total_score / 100` — AI 순위별 accent 컬러 |
| AI 총점 | `total_score.toFixed(1)` |
| AI 순위 | 🥇🥈🥉 이모지 (4위~ 숫자) |

### 2.3 ① 말정보 컬럼

**데이터 표기 원칙: 라벨 없이 값만 나열. 순서로 맥락을 전달.**

```
2세  수  ·  한국  R85                ← 나이 성 국적 레이팅 (monospace, 한 줄)
바람의딸(모) · 스타호크(부)           ← 혈통 (dim)
권승주 조교사 · 김대원 마주           ← 조교사 + 마주
5전 1/1/0/2/1  3,500만               ← 총전적(1위/2위/3위/기타/미완주) + 수득상금
485kg (+3)  ·  공백 18일             ← 마체중+증감 + 출전공백
1번 게이트 4전 1승(25%)              ← 게이트 성적 (3전+ 시 표시)
[장구변경] 블 추가                    ← 장구 변경 배지 + 항목
진료: 근육통 치료 (5/20)             ← pink, 진료내역 있을 때만

──────────────────────────────────── (divider)

⚡ 거리(1400m) 최고    ← 하이라이트 박스 (강조)
   1:25.3
   57kg · 양호 · 2위 · 3번 게이트

── 거리(1400m) 평균    ← 하이라이트 박스 (dim 버전)
   1:27.1
   3전 기준 · 전적 1/1/0
```

**총전적 형식:** `N전 W/P/S/R`
- W=1위, P=2위, S=3위, R=나머지(4위이하+미완주 합산)
- `R = sump_rcod_sum - fplc - splc - tplc`
- O(4위이하)와 X(미완주) 분리는 현재 DB 컬럼으로 불가 → 합산 표기.

**같은거리 기록:** 히스토리에서 `rc_dist === currentRace.rc_dist` 필터링해 client-side 계산.
- 최고: `min(rc_time)` + 그 경주의 `burd_wgt`, `track_type`, `ord`, `pthr_no`
- 평균: `avg(rc_time)` + 해당 거리 전적 W/P/S

### 2.4 ② 기수정보 컬럼

```
박태종  51kg                          ← 기수명(굵게) + 기수체중(wg_jk)
55kg (+1)  부담중량                   ← 부담중량 + 전경주 대비 증감
340전 62승  18.2%                     ← 통산 출주/승수 + 단승률 (cyan)

──────────────────────────────────── (divider)
이 말과의 전적
3전  1승  /  연1  복2                  ← 조합이력

──────────────────────────────────── (divider)
▸ 최근 조교
5/27  출전조교
박태종 (기수)  85초

──────────────────────────────────── (divider)
▸ 진료내역
근육통 치료 (5/20)                    ← pink. 없으면 "진료내역 없음" (dim)
```

**데이터 소스:**
- 기수 체중: `race_entries.wg_jk`
- 부담중량: `race_entries.burd_wgt`, 전경주 대비: `history[0].burd_wgt`와 비교
- 통산 성적: `jockey_stats` 테이블
- 조합이력: `useJockeyHorseComboBatch` (이미 구현)
- 최근 조교: `training_logs` (이미 구현)
- 진료내역: `race_entries.latst_trea1_txt`, `latst_trea2_txt`, `latst_bledg1`, `latst_bledg2`

### 2.5 ③ 직전경주 컬럼

**테이블 형식. 각 경주 = 메인행 + 구간기록 서브행.**

**메인행 컬럼:**

| 컬럼 | 소스 | 비고 |
|---|---|---|
| 날짜 | `race_entries.race_date` | M/DD 형식 |
| 장소 | `race_entries.meet` | 서울/부경 |
| 거리 | `race_entries.rc_dist` | |
| 조건 | `races.prize_cond` | 일반/핸디/조건 등. **races 테이블 join 필요** |
| 주로 | `race_entries.track_type` | 양호/불량/중간 |
| 착순 | `race_entries.ord` | ①②③ 원문자, 컬러 코딩 |
| 기록 | `race_entries.rc_time` | 빠른 기록 green |
| 중량 | `race_entries.burd_wgt` | |
| 기수 | `race_entries.jcky_nm` | |

**구간기록 서브행 (colspan=9):**
```
코너 5-3-2-2  ·  출발 14.2s  ·  막판600m 35.8s  ·  막판200m 12.1s
```
- 코너: cyan, 구간시간: dim
- 서울: `sj_1c_ord~sj_4c_ord` / 부경: `bu_g4f_ord`, `bu_g2f_ord`
- 출발 200m: `se_s1f_acc_time` / `bu_s1f_acc_time`
- 막판 600m split: `rc_time - se_g3f_acc_time`
- 막판 200m split: `rc_time - se_g1f_acc_time`

**기록 조회 범위:** 최근 5경주 (`limit(5)`). 현재 히스토리 쿼리와 동일.

**prize_cond 확보 방법:**
- 히스토리 쿼리 시 `races` 테이블 별도 조회 또는 `race_entries`에 `prize_cond` 컬럼 backfill.
- 단기 해결: 히스토리 race_date/meet/rc_no 목록으로 races 일괄 조회 → Map으로 매핑.

### 2.6 ④ 항목점수 컬럼

- 바 / 레이더 토글 (현재 구조 유지)
- TOP5 항목: 가중치 상위 5개 동적 선택 (현재 구조 유지)
- 바 수치: `rawScore` 표시 (0.00 ~ 1.00)
- 하단: AI 순위 이모지 + 총점 (컬러는 AI 순위 accent)
- 레이더 차트 높이: 나머지 컬럼과 균형 맞게 조정 (현재 220px → 컬럼 실제 높이에 맞춤)

## 3. 변경되는 것 vs 유지되는 것

### 변경

| 항목 | 변경 내용 |
|---|---|
| 말정보 레이아웃 | 라벨 제거 → 데이터만 표기. 같은거리 최고/평균 하이라이트 박스 추가 |
| 기수정보 | 기수체중(`wg_jk`) 추가. 조교·진료·조합이력 기수정보 컬럼으로 이동 |
| 직전경주 | 경기조건(`prize_cond`) 컬럼 추가. races 테이블 join 필요 |
| 항목점수 | 레이더 차트 높이 밸런스 조정 |

### 유지

- 4열 그리드 구조 (grid-template-columns 비율만 조정)
- 구간기록 서브행 (코너순위 + 3개 구간시간) — 최근 커밋 그대로
- 바/레이더 토글 로직
- TOP5 동적 선택 로직
- 포디엄 카드 + ComboBetBox (카드 위 상단 고정)
- 모바일 아코디언 레이아웃 (md: 미만 기존 구조 유지)

## 4. 구현 범위 및 주의사항

### 신규 데이터 페치
- `prize_cond`: races 테이블 일괄 조회 → `Map<string, string>` (key: `race_date-meet-rc_no`)
- `wg_jk`: 이미 `race_entries`에 존재, 타입 선언 있음 — UI 표시만 추가

### 같은거리 기록 계산
- 현재 히스토리 limit=5 → 같은거리 필터 후 최소 3건이 나오려면 최대 10건 필요할 수 있음
- 히스토리 limit을 `10`으로 늘리되, 화면엔 최근 5건만 표시

### 총전적 형식 변경
- 현재: `N전 (W-P-S-R)` → 신규: `N전 W/P/S/R` (슬래시 구분, 의미 동일)

### 모바일 대응
- 이번 재설계는 **데스크탑 전용**. 모바일(md: 미만) 아코디언은 별도 작업.
- `hidden md:grid` 패턴으로 분기 유지.
