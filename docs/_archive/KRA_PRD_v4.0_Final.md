# 🏆 KRA 한국 경마 분석 앱 - PRD v4.0 (PM 프레임워크 적용)

**최종 확정일:** 2026-05-22  
**버전:** v4.0 (v3.2 + PM 분석 통합)  
**작성 방식:** Product-Manager-Skills prd-development 프레임워크 적용  
**기술 스택:** React + Vercel + Supabase PostgreSQL (완전 무료)

---

## 1. Executive Summary (요약)

**KRA Analyzer Pro**는 한국 경마(서울·부산경남) 전문가/세미프로 사용자가 14개 데이터 항목을 자동 수집·분석하여 분석 시간을 **30분에서 5분으로 단축(-83%)** 하고, **스피어만 상관계수 기반 자동 학습**으로 적중률을 **+15%p 향상**시키는 AI 분석 도구다. KRA 공식 API 5개로 데이터를 자동 수집하고, PostgreSQL에 캐싱하여 빠른 분석을 제공하며, 모든 점수의 데이터 근거를 투명하게 공개해 사용자 신뢰를 확보한다.

## 2. Problem Statement (문제 정의)

### Who? (누구의 문제인가)
- **Primary:** 35-45세 데이터 기반 경마 분석가 (박정수 페르소나)
- **Secondary:** 28-35세 경마 입문자 (김다영 페르소나)

### What? (어떤 문제인가)
경마를 진지하게 분석하는 사용자들이 **14개 이상의 변수를 동시에 고려해야 하지만**, 다음과 같은 문제를 겪고 있다:

1. **데이터 분산:** KRA 공식 데이터가 여러 API/페이지에 흩어져 통합이 어려움
2. **시간 낭비:** 1경주당 30-60분 소요, 하루 10경주면 5-10시간!
3. **주관성:** 항목별 가중치를 직관으로 정해 일관성 없음
4. **학습 부재:** 과거 실수가 다음 분석에 반영되지 않음
5. **검증 불가:** 자기 분석 방법이 객관적으로 옳은지 확인 어려움

### Why Painful? (왜 고통스러운가)
- **경제적:** 잘못된 베팅으로 인한 직접 손실
- **시간적:** 본업/취미 시간 부족
- **심리적:** "최선을 다했나"하는 불안감
- **사회적:** "데이터 분석 안 한 사람"으로 보이고 싶지 않음

### Evidence (근거)
- **시장 조사:** 한국 경마 시장에 14개 항목 통합 분석 도구 부재
- **인터뷰 (가설):** 경마 커뮤니티에서 "분석 도구 추천" 글 다수
- **데이터:** KRA 베팅 시장 연 7조원+ → 분석 도구 수요 충분

## 5. Solution Overview (솔루션 개요)

### Core Value Propositions
1. **🤖 자동 데이터 수집** - KRA API 5개 자동 호출 + DB 캐싱
2. **📊 14개 항목 점수화** - 객관적 0~100점 종합 점수
3. **🧠 스피어만 학습** - 적정 가중치 자동 역산 + 점진적 수렴
4. **🔍 투명한 근거** - 모든 점수의 데이터 출처 공개
5. **📱 반응형 디자인** - 모바일+데스크탑 모두 최적화

### High-Level Architecture
```
┌─────────────────────────────────────┐
│  React (Vercel)                      │  ← 프론트엔드
│  ├─ 다크모드 + 데이터 중심 디자인     │
│  └─ PWA (모바일 지원)                │
├─────────────────────────────────────┤
│  Vercel Serverless Functions         │  ← 백엔드
│  ├─ /api/predict                     │
│  ├─ /api/backtest                    │
│  └─ /api/sync                        │
├─────────────────────────────────────┤
│  Supabase PostgreSQL (500MB)         │  ← DB
│  └─ 5개 테이블 + 인덱스              │
├─────────────────────────────────────┤
│  KRA Public Data APIs (5개)          │  ← 외부 데이터
│  ├─ API214_1, API4_3                 │
│  ├─ racedetailresult                 │
│  └─ API284, horseinfohi              │
└─────────────────────────────────────┘
```

### Key User Flows

#### Flow 1: 첫 사용 (Onboarding)
```
1. 회원가입 (이메일 또는 GitHub)
2. KRA API 키 입력 (또는 데모 모드)
3. 과거 2년 데이터 자동 수집 (백그라운드)
4. 백테스트 자동 실행 (가중치 초기화)
5. 첫 경주 예측 시작
```

#### Flow 2: 일상 분석
```
1. 대시보드: 오늘의 경주 일정 확인
2. 경주 선택 → 분석 화면 진입
3. 14개 항목 점수 자동 계산 (5초)
4. 출전마 순위 + 1-3위 확률 표시
5. PDF 리포트 생성 (선택)
6. (경주 후) 실제 결과 입력 → 학습
```

#### Flow 3: 학습 진화 확인
```
1. 통계 페이지 진입
2. 적중률 추이 차트 확인
3. 항목별 상관계수 변화 분석
4. 가중치 히스토리 검토
```

## 7. User Stories & Requirements

### Epic 1: Onboarding (온보딩)

**US1.1.** As a 신규 사용자, I want 간단한 회원가입을 하고 싶다, so that 빠르게 서비스를 시작할 수 있다  
- ✅ Acceptance: 이메일/GitHub 로그인, 30초 이내 완료

**US1.2.** As a 신규 사용자, I want KRA API 키를 안전하게 입력하고 싶다, so that 내 데이터가 보호된다  
- ✅ Acceptance: 암호화 저장, 사용자만 접근 가능

**US1.3.** As a 신규 사용자, I want 과거 데이터 수집 진행률을 보고 싶다, so that 기다리는 시간이 지루하지 않다  
- ✅ Acceptance: 실시간 진행률 + 예상 완료 시간

### Epic 2: Race Analysis (경주 분석)

**US2.1.** As a 분석가, I want 오늘의 경주 일정을 한눈에 보고 싶다, so that 분석할 경주를 빠르게 선택할 수 있다  
- ✅ Acceptance: 서울/부산경남 모두, 경주별 거리/등급 표시

**US2.2.** As a 분석가, I want 출전마 14개 항목 점수를 그래프로 보고 싶다, so that 강약점을 즉시 파악할 수 있다  
- ✅ Acceptance: 막대그래프 + 항목별 색상 + 호버 시 상세

**US2.3.** As a 분석가, I want 각 점수의 데이터 근거를 확인하고 싶다, so that 추천을 신뢰할 수 있다  
- ✅ Acceptance: 각 항목 클릭 시 데이터 출처 + 계산 과정

**US2.4.** As a 분석가, I want 두 말을 비교 분석하고 싶다, so that 결정적 차이를 파악할 수 있다  
- ✅ Acceptance: 사이드 패널, 항목별 점수 차이 + 핵심 차이 강조

### Epic 3: Reports (리포트)

**US3.1.** As a 분석가, I want 분석 결과를 PDF로 다운받고 싶다, so that 현장에서 종이로 참고할 수 있다  
- ✅ Acceptance: A4 1-2장, 핵심 정보 포함, 즉시 생성

**US3.2.** As a 분석가, I want 과거 리포트를 아카이브로 보관하고 싶다, so that 패턴을 분석할 수 있다  
- ✅ Acceptance: 날짜별/경마장별 검색, 무제한 저장

### Epic 4: Results & Learning (결과 입력 및 학습)

**US4.1.** As a 분석가, I want 경주 후 실제 결과를 빠르게 입력하고 싶다, so that 학습 데이터가 누적된다  
- ✅ Acceptance: 1경주 결과 입력 30초 이내

**US4.2.** As a 분석가, I want 내 적중률 변화를 시계열로 보고 싶다, so that 학습 효과를 확인할 수 있다  
- ✅ Acceptance: 일/주/월별 차트, 항목별 기여도

### Epic 5: Mobile Experience (모바일)

**US5.1.** As a 분석가, I want 경마장에서 모바일로 빠른 확인을 하고 싶다, so that 현장 결정에 도움 받는다  
- ✅ Acceptance: 5초 이내 로딩, 핵심 정보 한 화면

**US5.2.** As a 분석가, I want 오프라인 모드도 사용하고 싶다, so that 통신 끊겨도 분석 가능하다  
- ✅ Acceptance: PWA, 다운로드 후 캐시 사용

## 9. Dependencies & Risks

### Dependencies (의존성)

| 항목 | 위험도 | 대응 |
|------|--------|------|
| KRA API 안정성 | 🟡 중 | API 모니터링, 캐싱 강화 |
| Supabase 무료 한도 | 🟢 낮음 | 50MB 예상, 500MB 한도 |
| Vercel 함수 한도 | 🟢 낮음 | 월 100GB-h 한도 |
| Claude API (Phase 4) | 🟡 중 | 선택적 기능 |

### Risks (위험)

**Technical Risks (기술적)**
- 🟡 **R1:** KRA API 응답 형식 변경 → API 클라이언트 추상화, 모니터링 강화
- 🟢 **R2:** 데이터 수집 실패 → 재시도 로직, 부족 시 사용자 알림
- 🟡 **R3:** 가중치 학습 과적합 → 점진적 수렴 + 백테스트 검증

**Business Risks (사업적)**
- 🔴 **R4:** 법적 리스크 (베팅 보조 도구) → 법률 자문, 사용 약관 명시
- 🟡 **R5:** 사회적 인식 (사행성) → 분석 도구로 포지셔닝, 책임감 강조
- 🟡 **R6:** 시장 수요 부족 → 베타로 검증, 데이터 기반 결정

**Operational Risks (운영적)**
- 🟢 **R7:** 1인 개발자 한계 → MVP 우선, 점진적 개발
- 🟡 **R8:** 사용자 지원 부담 → FAQ, Discord 커뮤니티
